# 结构化抽取试点报告（2026-10-12）

## 样本

分层抽 45 条：推理 28 条（覆盖 15 个旧类别 + KV 扩展），训练 17 条（覆盖全部 16 个前缀）。
清单见 `sample_ids.txt`。每轮多路独立抽取，分批方式不同；`compare.py` 计算两两一致率。

## 结果

| 字段 | v0 Opus↔Sonnet | v1 Opus↔Opus | v1 Opus↔Sonnet |
|---|---|---|---|
| kind | 100% | 100% | 96% |
| 原因子系统（主） | 71% | **93%** | **91%** |
| 栈（主） | 87% | 98% | 100% |
| 影响对象（主） | 87% | 91% | 84% |
| 影响对象（至少一项重合） | 98% | 100% | 98% |
| 可见性 | 80% | 98% | 91% |

- v1 三路中 39/45 条子系统完全一致，44/45 条至少两路一致。
- 长度超限：v0 Sonnet 约一半超限；v1 收紧为硬约束并要求自检后，三路都是 0。
- “拿不准”标记：v0 Opus 标了 38/45，没有筛选作用；v1 收紧条件后每路 6–9 条。单看 Opus A 路，它标中了与 Opus B 的全部 3 条分歧，以及与 Sonnet 的 6 条分歧中的 4 条。
- 影响对象的分歧多是两项顺序互换，或多写/少写一个次要对象。

## 词表修订

- **v0 → v1**（基于四路一致报告的缺口）：
  - 新增影响对象 `输入编码`、`性能/资源`；
  - `服务可用性` 扩为 `可用性/进度`，覆盖训练作业中断；
  - `跨请求数据` 扩为 `跨请求/跨样本数据`，覆盖训练 packing 跨文档泄漏；
  - 新增可见性 `不可复现`、`性能退化`；
  - 新增 5 条判定规则，核心是“功能域优先”。
- **v1 → v1.1**（只改描述）：
  - KV缓存 / KV状态 覆盖 SSM 循环状态；
  - LoRA 计算 kernel 归 `算子/内核`；
  - 新增规则“触发条件不是对象”。

## 遗留问题（迁移不能解决，需后续阶段处理）

- **打包条目**：INF-0294（rowhammer 攻击 + HBM 磨损）、TRN-0134（Triton + Megatron 两个缺陷）、INF-0317 等，一条里装了不同机制，各路在这些条目上分歧最大。应在“模式/实例分层”阶段拆分。
- **悬空变体链接**：45 条（推理 42 / 训练 3），`var:` 指向的名称在编目中不存在。
- **缺字段**：INF-1239 原文没有行为效应字段，可见性只能填 `待定`。

## 全量迁移建议

- 剩余 1562 条，Opus 单路抽取，每批约 23 条，约 68 批；按试点用量估算，子 agent 合计约 650 万 token。
- 抽取后由 `validate.py` 硬校验；`uncertain` 非空的条目进人工复核队列，约占 15–20%；另随机抽 5% 做审计。
- 不建议全量双路：成本翻倍，而单路 `uncertain` 已经能捕获大部分分歧。
