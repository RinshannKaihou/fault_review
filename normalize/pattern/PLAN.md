# 阶段 B 重估：模式/实例分层

状态：**已重估，待用户定 2 个结构问题后开工。** 10-14 的估算（约 4400 次网关调用）作废。

## 重估的起点：A 留下的两个结论

1. `var` 的实际语义是「家族指针」，比文档定义（同一具体机制的不同显形）宽得多。
2. **没有可用的「同家族」判定模型**：对编目已接受的 8 对 var，严格 prompt confirm 0/8、
   极简 prompt 2/8，而两者都正确否掉 8 对随机。证据见 `normalize/relink/REPORT.md`。

第 2 条是 B 的关键路径——和 A 卡住的是同一件事。

## 现有结构已经是一个模式层

425 条已解析 var 边，**每个条目最多一条出边**，所以这张图是**森林**：

| | |
|---|---|
| 树（连通分量） | **199** |
| 覆盖条目 | **624**（占 1671 的 37%） |
| 孤立条目 | 1047 |
| 树大小分布 | 2 个:113 棵、3:44、4:17、5:8、6:3、7:5、8:2、9:4、12:1、16:1、**25:1** |
| 入度 ≥2 的条目（事实上的代表） | 77 |
| 既有入度又有出度（链式而非星形） | 80 |

199 棵树就是 199 个现成的候选模式。B 的第一步不需要任何判定调用。

## 嵌入相似度：可当候选生成器，**不能**当判定阈值

| 测量 | 结果 |
|---|---|
| var 关系对的余弦 | 中位 **0.718**，p10 0.638，p90 0.788 |
| 随机对的余弦 | 中位 0.566，p90 0.632，p99 0.703 |
| var 目标落在源条目近邻 top1 / top5 / top10 / top50 | 24% / 51% / **63%** / 83% |

排序有效（和 slug 相似度完全不同——那个中位只有 0.38、≥0.8 的仅 1/425）。

但阈值无效：**1047 个孤立条目，每一个都有 ≥0.638 的最近邻**，其中 816 个 ≥0.718（var 对的中位数）。
按余弦阈值聚类会把编目并成一团。所以候选可以自动生成，**成员资格必须靠判定**。

`cos ≥ 0.80` 的条目对共 134 对（10-14 估的 103 对已随编目增长），其中 57 对两端都已在家族里，
**77 对至少一端是孤立条目**——这是精度最高的一批扩展候选。

## 修订后的 B：三步，前两步成本很低

### 第 1 步：把现有森林固化成模式层（网关调用 ~0）

199 个模式文件 + 条目加 `pattern` 字段，覆盖 624 条。
成本不在判定，而在**schema 与工具改动**：两个编目仓库的 `catalog_tool.py` / `SCHEMA.md` /
`vocab.yaml`、`validate` 规则、RAG 的 parse 与检索投影、两份扫描说明（新条目要不要填 `pattern`）。
这一步的风险是改动面广，不是算力。

### 第 2 步：先把「同家族」的定义做出来（约 200 次调用）

这是 A 的教训直接转化的前置门槛，**不做这步就不要进第 3 步**：

1. 开放式归纳：对 30 对已接受的 var 关系，让模型描述「这两条共享什么」（不给定义），
   聚合这些描述，反推 `var` 在实践中的**实际**判据（约 30 次调用）。
2. 据此写判定 prompt，在 `relink.py` 那套 8 正 8 负标定集上迭代（每轮 16 对 × 2 模型 = 32 次）。
3. **放行门槛**：正例 confirm ≥6/8 且负例拒绝 ≥7/8。达不到就说明「同家族」无法自动判定，
   B 止步于第 1 步，第 3 步取消。

标定集要换成**留出集**（另抽 8 正 8 负，seed 不同），避免在迭代里过拟合那 16 对。

### 第 3 步：扩展到孤立条目（仅当第 2 步通过）

分批，每批先看产出率再决定下一批：

| 批次 | 候选 | 调用 |
|---|---|---|
| 3a | 77 对 `cos≥0.80` 且至少一端孤立 | 77 × 3 票 + 评审团 ≈ **280** |
| 3b | 孤立条目的 top-3 近邻（1047 × 3，去重后约 2500 对） | ≈ 9000 |
| 3c | top-10（约 10000 对） | ≈ 35000 |

3a 的产出率决定还做不做 3b。**不要一开始就承诺 3b/3c**——10-14 那个 4400 的估算
正是落在 3b 这一档，而当时并不知道判定模型能不能标定。
